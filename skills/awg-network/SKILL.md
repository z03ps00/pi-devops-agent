# Сетевой профиль

Профиль — запись `network.profiles` в локальной карте: id, подпись, контейнер или namespace, лаунчер. Не подставляй имя из другого стенда и не считай один туннель единственно возможным.

## Проверка

1. Контейнер или namespace профиля в состоянии Running. Иначе kill-switch должен останавливать запуск, а не пускать его на хост.
2. Подпись этой сессии — в футере `Net`, если карта задаёт профили. Файл режима хранит id для следующего запуска, не для уже идущего процесса.
3. `host` нужен для `virsh`, `apt` и host-`systemctl`. Скажи об этом и не обходи ограничение.
4. Утечка маршрута: сравни адрес выхода внутри профиля и на хосте. Они не должны совпасть, пока выбран туннель.

## Клиенты namespace

После пересоздания контейнера клиенты netns нужно восстановить штатным скриптом из индекса. Не создавай namespace вручную и не входи в чужой namespace, для которого в карте нет лаунчера.

## Блок доменов провайдера

Исключение — строка в файле allow, который называет индекс, затем штатный `apply`. Не `off` на весь блок.

`127.0.0.1` внутри netns — не хост. Адрес хоста из netns бери из индекса или заметки лаборатории.

## Заметка лаборатории

Пути, контейнеры, адреса и порты этой машины в скилл не входят. Блок локальной карты в системном промпте называет каталог `labSkillNotes`. Если там есть файл `awg-network.md`, прочитай его и следуй ему. Если каталога нет, скажи, что в `devops-local.json` не задан `labSkillNotes`, и не выдумывай путь.
