# Стек MCP

1. Прочитай `INDEX.md` в корне инфраструктуры из локальной карты и локальный `index.md` подсистемы. Это состояние. Скилл — процедура.
2. Управляй стеком штатным скриптом из индекса (`status`, включение, остановка, логи). Не поднимай произвольный `docker run`, если для сервиса есть compose-проект.
3. Смена порта, имени или порядка запуска обновляет индекс в том же изменении.
4. Проверки `curl` к хостовому порту делай из того сетевого режима, где этот адрес существует. В `awg` адрес `127.0.0.1` может быть не хостом. Адрес хоста — в индексе или в заметке лаборатории.
5. Контейнерные `docker ps`, `logs` и `compose ps` в `awg` идут через фильтрованный прокси, если карта его задаёт. Отказ 403 на host-сети — запрет, не обход.
6. Новый сервер MCP в профиль агента — `/mcpconfig`, не правка `mcp.json` в обход команды, пока режим не BUILD.

## Заметка лаборатории

Пути, контейнеры, адреса и порты этой машины в скилл не входят. Блок локальной карты в системном промпте называет каталог `labSkillNotes`. Если там есть файл `mcp-infra.md`, прочитай его и следуй ему. Если каталога нет, скажи, что в `devops-local.json` не задан `labSkillNotes`, и не выдумывай путь.
